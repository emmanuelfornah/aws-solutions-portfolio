# CloudWatch Logs Insights Queries for Security Monitoring

## Query 1: Failed Console Login Attempts
# Find all failed console login attempts with user details and source IP

fields @timestamp, userIdentity.userName, sourceIPAddress, errorMessage
| filter eventName = "ConsoleLogin" and errorMessage = "Failed authentication"
| sort @timestamp desc
| limit 20

## Query 2: Successful Console Logins
# Track successful console logins for baseline comparison

fields @timestamp, userIdentity.userName, sourceIPAddress, responseElements.ConsoleLogin
| filter eventName = "ConsoleLogin" and responseElements.ConsoleLogin = "Success"
| sort @timestamp desc
| limit 20

## Query 3: Failed Logins by User
# Aggregate failed login attempts by username

fields userIdentity.userName as User
| filter eventName = "ConsoleLogin" and errorMessage = "Failed authentication"
| stats count() as FailedAttempts by User
| sort FailedAttempts desc

## Query 4: Failed Logins by Source IP
# Identify IP addresses with multiple failed login attempts (potential brute force)

fields sourceIPAddress as SourceIP
| filter eventName = "ConsoleLogin" and errorMessage = "Failed authentication"
| stats count() as FailedAttempts by SourceIP
| sort FailedAttempts desc

## Query 5: Login Activity Timeline
# Visualize login attempts over time (successful and failed)

fields @timestamp, eventName, responseElements.ConsoleLogin, errorMessage
| filter eventName = "ConsoleLogin"
| stats count() by bin(5m)

## Query 6: IAM Policy Changes
# Monitor IAM policy modifications for security auditing

fields @timestamp, userIdentity.userName, eventName, requestParameters.policyName
| filter eventSource = "iam.amazonaws.com" and (eventName like /PutUserPolicy/ or eventName like /PutRolePolicy/ or eventName like /PutGroupPolicy/)
| sort @timestamp desc

## Query 7: Security Group Modifications
# Track changes to EC2 security groups

fields @timestamp, userIdentity.userName, eventName, requestParameters.groupId
| filter eventSource = "ec2.amazonaws.com" and (eventName like /AuthorizeSecurityGroup/ or eventName like /RevokeSecurityGroup/)
| sort @timestamp desc

## Query 8: Root Account Activity
# Monitor root account usage (should be minimal)

fields @timestamp, eventName, sourceIPAddress, userAgent
| filter userIdentity.type = "Root"
| sort @timestamp desc

## Query 9: EC2 Instance Launches
# Track EC2 instance creation events

fields @timestamp, userIdentity.userName, requestParameters.instanceType, responseElements.instancesSet.items.0.instanceId
| filter eventName = "RunInstances"
| sort @timestamp desc

## Query 10: S3 Bucket Deletions
# Alert on S3 bucket deletion attempts

fields @timestamp, userIdentity.userName, requestParameters.bucketName, errorCode
| filter eventName = "DeleteBucket"
| sort @timestamp desc

## Query 11: Failed API Calls (Access Denied)
# Find unauthorized access attempts across all services

fields @timestamp, userIdentity.userName, eventName, eventSource, errorCode
| filter errorCode = "AccessDenied" or errorCode = "UnauthorizedOperation"
| stats count() as DeniedAttempts by eventName, userIdentity.userName
| sort DeniedAttempts desc

## Query 12: MFA-Related Events
# Monitor MFA device changes

fields @timestamp, userIdentity.userName, eventName, requestParameters.userName
| filter eventSource = "iam.amazonaws.com" and (eventName like /MFA/ or eventName like /VirtualMFADevice/)
| sort @timestamp desc

## Query 13: Unusual API Call Volume
# Detect spikes in API activity (potential compromise)

fields eventName
| stats count() as CallCount by eventName, bin(5m)
| sort CallCount desc

## Query 14: Cross-Region Activity
# Identify API calls from unexpected regions

fields @timestamp, awsRegion, userIdentity.userName, eventName
| filter awsRegion not in ["us-east-1", "us-west-2"]
| sort @timestamp desc

## Query 15: Failed Login Attempts with Geolocation Context
# Combine failed logins with source IP for investigation

fields @timestamp, userIdentity.userName, sourceIPAddress, userAgent, errorMessage
| filter eventName = "ConsoleLogin" and errorMessage = "Failed authentication"
| sort @timestamp desc
| limit 50

## Query 16: Privileged Actions
# Monitor high-risk administrative actions

fields @timestamp, userIdentity.userName, eventName, eventSource
| filter eventName in ["DeleteTrail", "StopLogging", "DeleteLogGroup", "DeleteAlarm", "DeleteBucket"]
| sort @timestamp desc

## Query 17: Console Login Success Rate
# Calculate login success vs failure ratio

fields eventName, responseElements.ConsoleLogin, errorMessage
| filter eventName = "ConsoleLogin"
| stats count() as Total, 
        count(responseElements.ConsoleLogin = "Success") as Successful,
        count(errorMessage = "Failed authentication") as Failed

## Query 18: User Activity Summary
# Generate per-user activity report

fields userIdentity.userName as User, eventName
| stats count() as Actions by User
| sort Actions desc
| limit 20

## Query 19: API Calls by Service
# Understand which AWS services are most used

fields eventSource
| stats count() as APICallCount by eventSource
| sort APICallCount desc
| limit 15

## Query 20: Recent High-Risk Events
# Comprehensive security event query

fields @timestamp, userIdentity.userName, eventName, sourceIPAddress, errorCode
| filter (errorMessage = "Failed authentication") 
        or (eventName in ["DeleteTrail", "StopLogging", "DeleteBucket"])
        or (errorCode = "AccessDenied")
        or (userIdentity.type = "Root")
| sort @timestamp desc
| limit 50

## Usage Tips

1. **Time Range**: Always specify a time range to reduce data scanned and costs
2. **Limit Results**: Use `limit` to cap result set size
3. **Aggregations**: Use `stats` for counting, summing, and grouping
4. **Filtering**: Combine multiple filters with `and`/`or` for precise queries
5. **Sorting**: Use `sort` to order results by timestamp or metric values
6. **Binning**: Use `bin()` for time-series aggregations (e.g., `bin(5m)` for 5-minute intervals)

## Query Performance Optimization

- Use specific time ranges (e.g., last 1 hour instead of last 7 days)
- Filter early in the query to reduce data processed
- Avoid scanning large fields unnecessarily
- Use `limit` to cap result sets
- Consider creating metric filters for frequently queried patterns

## Exporting Results

1. Run query in CloudWatch Logs Insights
2. Click "Export results" button
3. Choose format: CSV or JSON
4. Use exported data for reporting, compliance, or SIEM integration

## Scheduling Queries

CloudWatch Logs Insights queries cannot be scheduled directly. Options:
- Use Lambda function with CloudWatch Events (EventBridge) to run queries programmatically
- Export logs to S3 and use Athena for scheduled queries
- Integrate with third-party SIEM tools for automated querying

## Cost Considerations

- Queries are charged at $0.005 per GB of data scanned
- Use time ranges and filters to minimize data scanned
- Consider creating metric filters for frequently monitored patterns (no query cost)
- Monitor query costs in CloudWatch billing dashboard
